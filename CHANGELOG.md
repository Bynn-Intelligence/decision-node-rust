# Changelog

All notable changes to this crate are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the crate follows [Semantic Versioning](https://semver.org/).

## [0.3.0] - Unreleased

Implements DecisionNode SDK specification version 1.3 (`SPEC_VERSION`): boosters and fine-tuned model names, checked against conformance suite 1.11 with the async and the blocking client.

### Added

- Depth Vision and Segment Vision: `Reading::BynnDepth(DepthReading)` for the `bynn_depth` booster (`ahead`, seven `directions`, `ground`, a `grid` of meters, `depth_min`, `depth_max`, `depth_median`, `width`, `height`) and `Reading::BynnSegment(SegmentReading)` for `bynn_segment` (`prompts` and `instances`, each a `SegmentInstance` with its `bbox`, `polygon`, `area`, `centroid` and, when sent, `opening`, `depth` and `size_m`), every number as sent; a reading of another shape is a `Reading::Unknown`. Their options are sent as given and checked by the API.
- Device keys: `DecisionNode::keys()` (and the blocking client's) with `create(&NewKey)` (`POST /v1/keys`, with an `Idempotency-Key`, yours or a new one kept across attempts, and the retries of a collection's create), `list(&KeyQuery)`, `all(&KeyQuery)`, `update(key_id, &KeyUpdate)` (whose `clear_` forms send `null`), `revoke(key_id)` and `revoke_by_labels(&KeyRevocation)`, each returning the API's objects as sent. A name, device id, label or daily spend cap the API would refuse, a bulk revoke without a label or with more than 1,000 devices, malformed list filters, a `limit` outside 1 to 200, an `Idempotency-Key` that is not 1 to 255 printable ASCII characters and an empty change are refused before anything is sent, with the API's own error.
- Usage by key: `DecisionNode::usage()` (and the blocking client's) with `key(key_id, &UsagePeriod)` for `GET /v1/keys/{key_id}/usage`, `list(&UsageQuery)` for `GET /v1/usage` and `all(&UsageQuery)`, which follows `next_cursor` until it is `null`, each returning the API's objects as sent. The query rules the API checks are refused before anything is sent, with its own error and message.
- `rustls` 0.23.46 in `Cargo.lock`.
- A `429` `key_spend_cap_reached` (a key's daily spend cap, whose wait runs to 00:00 UTC) is raised at once as a `RateLimit` error and never retried; every other `429` is retried as before.
- `ModelInfo::price_per_million_input`, `price_per_million_output`, `price_per_million_image`, `price_per_million_video` and `batch_price_factor`, read as sent and `None` when the entry does not state them; they stay in `limits` too.
- `FaceRecognitionReading::collection_name`, and on each `FaceMatch` its `collection_name` and its enrolled face's `metadata` (the object as sent), each `None` when absent; one present but of the wrong type makes the reading a `Reading::Unknown`.
- Collections items: `enroll` takes `metadata`, sent only when given; `update_item` with an `ItemUpdate` (`reference`, `label`, `clear_label`, `metadata`) changes an item, sending only the fields set, with an `Idempotency-Key` and the retries of `enroll`; `list_items_with` takes an `ItemQuery` with `offset`, `limit`, `reference` and `reference_prefix`. Metadata (an object of at most 20 keys of 1 to 40 of `a-z`, `0-9` and `_`, each value a text of at most 500 characters, a number or a boolean), an empty change and a malformed or doubled reference query are refused before anything is sent, with the API's own error. `Error::details` holds the error body's `detail.details`; a `529` whose reason is `enrollment_unpriced` is not retried.
- Collections of faces: `DecisionNode::collections()` (and the blocking client's) with `create`, `create_with_type`, `list`, `get`, `delete`, `enroll`, `list_items` and `delete_item`, each returning the API's object as sent. `create` and `enroll` send an `Idempotency-Key`, a new random UUID for each call and the same on every attempt of it, so the API applies them once; they are retried as every call is and also on a `409` `idempotency_in_progress`, while a `409` `idempotency_key_reused` is returned as the base error. A collection type other than `face`, a name not 1 to 80 characters, a reference not 1 to 64 of `A-Z`, `a-z`, `0-9`, `_`, `.`, `:` and `-`, an empty label or one over 128 characters, an enrolled image's URL that a decision's would refuse and a `list_items` page outside its bounds are refused before anything is sent, with the API's own error (a long input echoed as its first 64 characters and `...`, as the API echoes it). `Reading::FaceRecognition(FaceRecognitionReading)` (`image`, `faces`, `matches` of `FaceMatch` with `bbox`, `score`, `collection`, `reference`, `name` and `label`) replaces the unreleased `wanted_person` reading.
- Several places in one answer: `Point::max` and `BoundingBox::max` (sent only when given) ask for up to that many spots or rectangles, answered by `Answer::Points(PointsAnswer)` (`count`, `present`, `complete`, `points` of `PlacePoint`, `image`, `width`, `height`) or `Answer::Boxes(BoxesAnswer)` (`boxes` of `PlaceBox`), told apart by the answer's own list and with every number as sent; a malformed one is `Answer::Unknown`. A `max` that is not a whole number from 2 to 16 is refused locally with the API's `Validation` entries; whether a model serves several places is left to the API.
- A request naming the `ocr` booster waits `DEFAULT_OCR_TIMEOUT` (30 seconds) per attempt when no timeout was set, while a timeout set with `ClientBuilder::timeout` is used as given; such a decision is never retried after a timeout, since the server may bill the attempt, and keeps its other retries. `decide`, the helpers and each `decide_many` request follow it, with the async and the blocking client; sessions, batches and `decide_raw` do not.
- Boosters: a list of names, `.boosters(["age", "ai_generated"])`, sent as `"boosters": ["age", "ai_generated"]`; `Booster` for a booster with a setting (`Booster::new(name)` with `image`, `images`, `require` and `options`, sent as `{"name": name, ...}`, or as the plain name when none is set; a plain name, `"age"`, converts into one and is sent as the string; a `serde_json::Value` in the wire form is sent as given), and `DecideRequest::booster` / `boosters` and `CallOptions::booster` / `boosters`. The helpers, `decide_many`, batch requests and `check_decide` take boosters as `decide` does; sessions do not. The list keeps the caller's order, and a request without boosters has no `boosters` key. Nothing about boosters is checked locally except that the list counts toward the 128-level nesting limit.
- `Decision::evidence`: one `Evidence` per booster the request named, by name in the request's order (`version`, `status`, `latency_ms`, `billed_calls`, `results`, `raw`), `None` when it named none. Readings are `Reading::Age(AgeReading)`, `Reading::AiGenerated(AiGeneratedReading)` with `TopGenerator`, and `Reading::Unknown(UnknownReading)` for a booster this version does not know or a reading with a field missing or of the wrong type, so the decision never fails on one.
- `Usage::booster_tokens` and `Usage::boosters`, `None` for a request without boosters.
- `Usage::cost`: what each answer cost, as the API sends it, a `Cost` with `usd`, `model_usd`, `boosters_usd` and `free_tier`, read as sent and never computed (`usd` is the API's figure, not the sum of the parts); `None` when the server does not send it. Decisions, batch results and session replies carry it.
- Fallback: `DecideRequest::fallback` and `CallOptions::fallback` (the helpers, `decide_many` and batch requests take it too), sent as `"fallback"` only when set; `Decision::fallback`, a `Fallback` with `served_model` and `requested_model` from the `x-decisionnode-fallback` and `x-decisionnode-requested-model` headers, `None` on an ordinary answer.
- `Error::boosters`: the `x-decisionnode-boosters` header parsed into booster name to `BoosterStatus` (`status`, `latency_ms`), in the request's order, on every error from a response; empty when the header is absent.
- `ModelInfo::fine_tuned`, `base`, `adapter_version` and `status` for a workspace's fine-tuned models, `None` on a catalogue entry.
- The API's 25 MiB request body limit: `MAX_BODY_BYTES` (26,214,400) and `ErrorKind::RequestTooLarge` (`RequestTooLargeError`). The body is measured as it would be sent, inline images and video frames included and an image the client would upload named by its upload id, before anything is sent or uploaded: over the limit, `decide`, the helpers, `decide_many` (the whole call), each batch line and `check_decide` / `check_batch` fail with `RequestTooLarge`, no status, `error_type` `request_too_large_error` and the API's message. `decide_raw` sends its body as given.

### Changed

- `Batch` no longer has `price_factor`: the batch price is each model's, the `batch_price_factor` its `models()` entry lists, and each result line's charge is in its `usage`.
- `Usage` is `Clone` but no longer `Copy`, since it holds the answer's `Cost`.
- The default model is `decisionnode-moe` (it was `decisionnode-latest`). The documentation and examples use the family ids `decisionnode-moe` and `decisionnode-flash`, which mean the current release of each family; an answer names the pinned id that answered (`decisionnode-<family>-<version>`), and `models()` lists the pinned ids. `model` stays free text.
- `SPEC_VERSION` is `"1.3"`.
- A fine-tuned model's name (`decisionnode-flash@acme/fraud`, `...:3`) is a model like any other: sent as given, never parsed locally, and `Decision::model` carries the pinned name that answered.
- The API's 413 is `RequestTooLarge`, never retried (the base kind before).
- An error status whose body is not JSON (a proxy's or the network edge's own page, or no body) is classified by its status alone, with `error_type` `None`, the request id and reason from their headers, and the message `HTTP <status> <status text>` (for example `HTTP 413 Content Too Large`, then ` (request id <id>)` when sent); the body is never read into any field. A 400 without a JSON body is `BadRequest`, a 403 `PermissionDenied` and a 422 `Validation` with empty entries. Retries follow the status as before.
- An image id longer than 64 characters, counted as Unicode code points, is refused before sending with the API's `BadRequest` `api_usage_error` `Image <n>: its id is longer than 64 characters.` (the image counted from 0), after the empty-id check and before the duplicate check, on every body that carries the ids: `decide`, the helpers, `decide_many`, batch lines and the checks. A session frame's image, which goes without its id, and `upload` are not checked for it.
- `booster_unknown`, `booster_input_mismatch` and a malformed `boosters` list are `BadRequest` errors; `booster_not_enabled` and any other 403 that is not a refusal are `PermissionDenied`; `booster_unavailable` is `Overloaded` and retried like every 529.

## [0.2.0] - Unreleased

Implements DecisionNode SDK specification version 1.2 (`SPEC_VERSION`): sixteen images, videos as frames, and the point and box question types, checked against conformance suite 1.10 with the async and the blocking client.

### Added

- Point and box questions: `point` and `bounding_box` (named for the wire type `box`, a reserved word in Rust), with `.image(id)` and `.units(...)`, and the answers `Answer::Point(PointAnswer)` (`x`, `y`, `present`, `confidence`, `image`, `width`, `height`) and `Answer::Box(BoxAnswer)` (`x1`, `y1`, `x2`, `y2` and the same), read with `as_point` and `as_box`. An answer with a field missing or of the wrong type is `Answer::Unknown`. Their rules are checked locally with the API's 422 entries: an image in the request, `image` naming one of them (required with two or more), and the units; a point or box without instructions is the API's 400.
- Videos sent as the frames the caller sampled: `Video` (`Video::new(id)` with `frame`, `frames`, `fps`, `start` and `end`) and `VideoFrame` (`bytes`, `bytes_with_type`, `base64`), and `DecideRequest::video` / `videos` and `CallOptions::video` / `videos`. A `serde_json::Value` in the wire form converts into either and is checked by the same rules. The helpers, `decide_many`, batch requests and `check_decide` take videos as `decide` does. Frames always go inline: they are never uploaded, cached, resized or re-encoded.
- The API's video rules are checked before anything is sent, with the API's own message: an id that is present and unique across images and videos, at least one frame, frame times at least 0 and strictly increasing, a JPEG, PNG or WebP media type for every frame, `fps` above 0 and at most 4, `start` and `end` at least 0 and `end` after `start`. The number of frames, their sizes and their pixels are left to the server.
- `Usage::video_frames` and `Usage::video_seconds`, `None` for a request without videos, and `Decision::warnings`, the server's notes exactly as sent, empty when there are none.

### Changed

- `SPEC_VERSION` is `"1.2"`.
- Up to 16 images a request, all of a request's uploads in one presign of up to 16 files. More than 16 images, or more than 4 videos, is refused locally as the API's 422: a `Validation` error with a `too_long` entry on `["body", "images"]` or `["body", "videos"]`, listed after the request's other entries. `upload` with more than 16 images returns the presign's own 400, "files: 1 to 16 files, got 17.".
- A model's image and video limits held from `models()` are also read where the API publishes them, in its `images` and `videos` objects.
- `Usage` is no longer `Eq`, since `video_seconds` is a floating-point number.

## [0.1.0] - Unreleased

First release, implementing DecisionNode SDK specification version 1.1 (`SPEC_VERSION`): every public call, checked against conformance suite 1.6 with the async and the blocking client.

### Added

- `DecisionNode`, an async client for `POST /v1/decide` and `GET /v1/models`, configured by arguments, the `DECISIONNODE_API_KEY`, `DECISIONNODE_BASE_URL` and `DECISIONNODE_MODEL` environment variables, and defaults.
- `decide`, `decide_many` (input order, at most 8 at a time by default; every request is checked before any is sent, so an invalid request is an argument error or the API's own error, a concurrency below 1 an argument error, and nothing is sent), `check`, `classify`, `score`, `gate`, `models` and `decide_raw`, with `*_with` variants of the helpers for images and a model.
- `gate` with fixed question wording, the same in every DecisionNode SDK.
- An empty key, base URL or model counts as not given: the environment, then the default, applies.
- Question builders `truth`, `choice` and `score`; plain JSON questions in the wire form are accepted too.
- Typed answers: `TruthAnswer`, `ChoiceAnswer`, `ScoreAnswer`, and `UnknownAnswer` for answer types this version does not know and for known types with missing or wrongly typed fields, so one odd answer never fails a decision; `ModelInfo` for each entry of `models()` and `DecisionResult` for each result of `decide_many`. Numbers are passed through unrounded, and a missing token count or latency is `None`, never 0.
- Images from an `https` URL (the recommended form), a file path, bytes, base64 text or an upload id. A file is read when the `Image` is made; the media type of local bytes is read from the first bytes (JPEG, PNG or WebP), and a type named with `Image::bytes_with_type` must match them. Local images go inline as base64 when a request's local images total under `DEFAULT_INLINE_THRESHOLD` (524,288 bytes, `ClientBuilder::inline_threshold`), and are uploaded at or above it: one `POST /v1/uploads`, the `PUT`s in parallel with exactly the returned headers (never the key or the client's headers, no redirects), then `upload_id`. An in-memory cache by SHA-256 (256 entries, until 5 minutes before expiry) sends bytes uploaded before by their `upload_id` whatever their size, and requests holding the same bytes at once share one upload. A stale upload the client placed is uploaded again and the request resent once. A storage `PUT` answered `403` once its URL's 5 minutes have passed is presigned again once. Each `PUT` attempt has its own timeout, `DEFAULT_UPLOAD_TIMEOUT` (60 s, `ClientBuilder::upload_timeout`), apart from the API call's. `upload(images)` uploads explicitly. `ClientBuilder::clock` replaces the clock uploads are judged by, for tests.
- Every fixed rule the API documents is checked before any request, in the server's order, and a fault is what the server would answer with no status (`Error::is_local`): the same kind, the same `error_type` (none for the plain-text 400s, `api_usage_error`, `image_url_refused` for a refused image URL), the documented message, and for a 422 a `Validation` error whose `entries()` are exactly the server's list. Covered: the 128-level nesting limit; unknown question types; questions without a type or criteria, or with fields of the wrong type; choices of 1 to 255 options, scores of 1 to 10 levels, a truth with instructions or criteria; number grids (`float_type`, 2^53, 6 decimals, the 15-digit bound, `min` above `max`, 4,096 values) and their instructions; a state of the wrong type; images (count, ids present and unique, format, 10 MB, 40 megapixels from the PNG, JPEG or WebP header, an upload reference's media type) and image URLs (`https`, 2,048 characters, no user information, port 443, no literal private or reserved address); session `window` (1 to 64) and `ttl_seconds` (1 to 3,600); every rule of a session frame, refused by `Session::send` with nothing written and no `seq` used; `batches().list` paging; batch `custom_id` rules and an empty add. Limits that `/v1/models` states (choice options, score levels, grid size, images, number support, session window and TTL, whether a model serves sessions, `requests_per_batch`, `max_custom_id_chars`) are checked against the list from the client's last `models()` call, found by the model's name or by the alias or pinned version an entry states, and left to the server when the list states neither.
- `check_decide`, `check_session`, `check_batch`, `check_batch_add` and `Session::check_frame` run every local check the call would run, with the held limits, and return the same error, sending and uploading nothing.
- `number` questions (`number`, `Number`, `NumberAnswer`, the `number` helper).
- Sessions (default `sessions` feature, framed by tokio-tungstenite over a connection of the client's own HTTP settings: proxy, root certificates, client certificate): `open_session`, `Session::connect`, `send`, `next_event`, `replies`, `end`, `close`, typed `Reply`, `FrameError` and `SessionClosed`, `supervise` with reopening on the reopen codes, and `ErrorKind::SessionLimit` for a `429` `session_limit_exceeded`, never retried.
- The Batch API: `batches()` with `create` (JSON Lines), `add` (split at 10 MiB), `finalize` (a `409` resolved with `get`), `get`, `list`, `results` (the whole file, parsed line by line, errors as values), `stream_results` (read from the network line by line: a `Stream`, an `Iterator` in the blocking client) and `cancel`, and `run_batch` / `run_batch_with`. `create`, `add` and `finalize` retry only on `429` and `529`.
- The safety check result on every decision, parsed from `x-decisionnode-safety`.
- Typed errors by `ErrorKind`, with the server's reason, request id, refusal category, validation entries and `retry_after`. A 403 that is not a refusal is `PermissionDenied`; any status without a kind of its own, 3xx included, is the base `DecisionNodeError` (`ErrorKind::Other`) with its status. An error's `Display` and `message()` are the server's message exactly, `""` when it sent none. Arguments refused before sending are errors of the base kind without a status (`Error::is_argument`), not a kind of their own.
- Only 2xx is a success, and redirects are never followed, so the key is never sent to another URL. A 2xx whose body is not JSON is a `Server` error with the status, request id and the reason from `x-decisionnode-error`.
- `check`, `classify` and `score` return a `Server` error (status, request id, reason) when their own answer is missing or malformed, since they promise a typed answer; `decide` returns `UnknownAnswer` for the same answer.
- `HttpSettings`, passed with `ClientBuilder::http_settings`: proxy, root certificates, client certificate, connect timeout, pool and TCP options. The SDK builds its HTTP client itself and takes no client of the caller's making, so no setting can turn on redirects or turn off certificate and hostname checks.
- The base error is exported as `DecisionNodeError`, an alias of `Error`.
- The base URL must be `https`; plain `http` only for `localhost`, `127.0.0.1` and `::1`.
- A 10 second timeout per attempt, from sending to the last byte of the body (set as a `Duration` or with `timeout_secs`; a timeout of 0 or below and a negative `max_retries` are argument errors), and 2 retries on 408, 429, 5xx, timeouts and connection errors, honouring `retry-after-ms` and `Retry-After` (seconds or an HTTP date), capped at 60 s. `ClientBuilder::sleeper` replaces the wait between attempts, for tests.
- A blocking client behind the `blocking` feature, with every call, a blocking `Session` and the Batch API.
